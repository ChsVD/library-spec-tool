# GMP 单纯形形式化验证需求与顶层规约

本文是后续 QCP / Rocq 验证的需求基线。读者应能据此为唯一顶层公开入口写出前置条件、后置条件和内存谓词，并判断一个证明究竟覆盖了哪些返回路径。下文的“必须”“推出”均为**待证明性质**。本次只编写规约说明，尚未运行形式化验证。

**当前验证对象**是独立工程 P5 后续链表入口修订的源码工作树，顶层唯一入口为 `sx_check_qcp`。以下原 P5 归档及其哈希仅标识历史发布基线，不标识当前修改后的源码；当前修改未进行形式化验证。原 P5 正式版发布包为 `release/qcp-simplex-gmp-P5.tar.gz`，SHA-256 为 `48a76f9b933c16981aaa09130bc953c00b857b43dc98de05ea886731df25adf8`。文件级基线见同目录的 P5 manifest。主要接口见 [公开头文件](../include/sx_solver_contract.h)，实现见 [顶层控制](../src/solver.c)、[表操作](../src/table.c) 和 [算术层](../src/arith.c)。项目 MiniGMP 副本及其运行时属于实现依赖，不能假定可直接套用系统 GMP 的规约。

## 1. 工具回答什么问题

输入是一组必须**同时成立**的非严格线性不等式。设有 `m` 行、`n` 个原变量，第 `i` 行恰有 `n+1` 个精确整数。令

```text
eval(i, x)   = c[i,0] + Σ(j=0..n−1) c[i,j+1] · x[j]
SatQ(P, x)   = x ∈ ℚⁿ 且对每个 i < m，eval(i, x) ≤ 0
SatZ(P, z)   = z ∈ ℤⁿ 且 SatQ(P, embed(z))
embed        = 逐坐标把整数嵌入有理数
```

原 QCP GMP FME 的 [fme_rel.v](/home/maxu/Projects/qcp-v2.2.0/Rocq/MonadLib/Examples/fme_rel.v) 定义 `LP_sol := list Z`。新核心先求整数问题的**有理数放宽**，再给出保守的整数解释。对应旧定义时还要证明长度桥接：每行恰有 `n` 个变量系数；旧 `sum_prod` 在任一列表结束时停止，短赋值补零、长赋值截至 `n`，各行值不变。因此可把上述定长整数语义与旧 `satisfy_LP`、`UNSAT` 联系起来。不能仅因双方使用同一种链表就继承 FME 的证明。

所有原变量初始无上下界，可以取负值。等式由调用方拆成两条不等式。整数严格比较只有在两边取值保证为整数时，才能在放宽前将 `a < b` 转为 `a ≤ b−1`。核心不接受实数严格比较、析取或不等于。本次顶层目标不包括完整整数求解、SMT 搜索、增量回溯或证明生成。

## 2. 从 C 调用读出同一个数学输入

```c
void sx_check_qcp(const struct InequList *head, size_t variables,
                  const SxSolverLimits *limits, SxResult *out);
void sx_result_init(SxResult *out);
void sx_result_clear(SxResult *out);
```

| 项目 | 调用者提供的条件及逻辑解释 |
|---|---|
| QCP 链表入口 | 节点为 `{mpz_ptr coef; struct InequList *next;}`。从头到 `NULL` 顺序解码；末节点是有效约束。`head == NULL` 表示零行。合法输入链有限、无环，每个 `coef` 指向至少 `n+1` 个可读且已初始化的项目整数。 |
| 读权限 | 节点、各行系数、大整数头及有效 limb 在调用期间保持可读、存活且不变。共享只读系数或 limb 应用读权限表达，避免无依据地要求每行拥有独占内存。裸指针不能检查实际分配长度，也不能保证安全地诊断悬空地址。 |
| 写权限 | `out` 指向一个独立、可写、已初始化且为空的结果，与输入及其他借用对象不重叠。`limits` 可为 `NULL` 或指向在调用期间稳定的已初始化配置。对象按现有契约在同线程使用和清理。 |
| 边界 | `m=0` 是空合取；`n=0` 时每行只判断常数，合法见证是空向量。极大尺寸必须先做可表示性检查再做地址或字节运算。 |

建议建立两层前置条件。**数学路径**要求输入可解码为矩阵 `P`。**防御性路径**允许可安全检查的坏输入，例如节点地址有效但链有环、节点的 `coef == NULL`、无效配置或结构上可读但表示不合法的整数。后者只证明诊断与清理；先遇到预算限制时可先返回资源原因。任意无效地址不属于这两类的内存安全保证。`out == NULL` 的实际行为是直接返回，调用者收不到结果。

`sx_table.h` 保留内部压缩数组建表和 P2 独立底层测试接口；它们不属于顶层求解接口。原 `lia_deduction` 会改变输入链表；新入口只读输入，返回结果对象，不产出消元后的链表。

## 3. 顶层后置条件

顶层入口返回类型是 `void`。调用者必须检查 `out->error`，然后按枚举读取状态。下表省略枚举前缀 `SX_Q_`、`SX_Z_` 和 `SX_REASON_`。对一个满足前置条件且正常返回的调用，结果应恰属于以下一行。

| error | 有理数状态 | 整数状态 | reason | 必须建立的事实与允许发布的数据 |
|---|---|---|---|---|
| SX_OK | FEASIBLE | SAT | NONE | 发布原编号下长度为 `n` 的见证 `w`。证明 `SatQ(P,w)` 且每个坐标分母为 1，解码为整数后满足 `SatZ`。 |
| SX_OK | FEASIBLE | UNKNOWN | FRACTIONAL | 同样发布 `w` 并证明 `SatQ(P,w)`；至少一个分母大于 1。对是否存在其他整数解不作结论。 |
| SX_OK | UNSAT | UNSAT | CONFLICT | 证明 `∀ x∈ℚⁿ, ¬SatQ(P,x)`，由整数嵌入推出 `∀ z∈ℤⁿ, ¬SatZ(P,z)`。发布局部冲突记录，无见证。 |
| SX_OK | UNKNOWN | UNKNOWN | 资源原因 | 未完成判定，既不发布见证也不发布冲突。原因区分总空间 SPACE、事务空间 ARITH_SPACE、limb 上限 LIMBS、尺寸溢出 SIZE_OVERFLOW、换基上限 PIVOTS、时间上限 TIME。 |
| SX_INVALID / SX_OOM / SX_INTERNAL | NOT_RUN | NOT_DECIDED | 分别为 INVALID_INPUT / ALLOCATION / INTERNAL | 无数学输出。保留相应诊断；真实或注入的分配失败与可预测的预算耗尽分开。NOT_RUN 是公共错误状态，即使出错前已完成部分计算也使用它。 |

见证的每个分数要求分母正、最简，零为 `0/1`。长度为零时，见证指针可以为 `NULL`，应由状态和长度判断。仅 UNSAT 可有 `conflict.present = 1`；仅 FEASIBLE 可交付见证。统计允许描述已处理的前缀，不能用于推出数学结论。资源/错误路径还应检查 `diagnostic`，算术相关路径保留 `arithmetic_reason`；内部 `SX_LIMIT` 在顶层映射为资源 UNKNOWN。

**建议的 Hoare 规约骨架**（数学伪码，非已编译的 QCP 注解）：

```text
Require  InputRO(entry, P, m, n) * ResultEmpty(out) * ConfigRO(limits) * Frame
Ensure   InputRO(entry, P, m, n) * ResultOwned(out, R) * ConfigRO(limits) * Frame
         且 PublicPost(P, n, R)                         // 即上表之一
```

这里的 `InputRO` 包含原指针、次序、系数值及其读权限；`Frame` 是与求解器无关的调用方内存。`ResultOwned` 按状态描述独占的动态分数及冲突数组。坏输入另写安全诊断规约，不在前置条件中虚构矩阵。顶层安全性是“凡给出确定答案，必对原输入成立”；为防止把“总返回 UNKNOWN”当成完整验收，还应单独证明正常控制分支可产出见证或冲突，并用第 6 节实例覆盖它们。

## 4. 为什么能对原输入给出结论

1. **大整数与分数。** 建立项目整数、limb、符号和逻辑整数的表示关系，再证明导入、规范化、四则、比较与精确有理数一致。规约覆盖允许的输出别名、零、非法除数、尺寸检查、临时分配及失败回滚。使用未经证明的后端函数契约时，应列出假设和使用点。
2. **预处理。** 常数真行可删，常数正行直接构成矛盾；未使用变量删去后可补零；整行只除以正公因子，连同常数一起除，不做取整。证明原解可投影、活动解可提升为原解，行列编号与正比例因子可追溯。常数矛盾快判必须以完成输入验证为前提。允许的优化开关改变成本，不改变已发布结论的可靠性。
3. **建表与换基。** 为每条活动行引入表达式变量 `sᵢ = cᵢ₀ + Σ cᵢⱼ xⱼ`，加界 `sᵢ ≤ 0`。证明原解恰是满足扩展等式和界的赋值在原变量上的投影。始终保持基与非基构成划分、每行等式成立、非基赋值满足其界；修复过程中基变量允许越界。非零主元的换基须保持整个等式解集，界随变量身份保留，离基变量落在待修复的界上。候选表只有完整检查通过才提交；失败保留旧表并释放候选。
4. **见证路径。** 没有越界基变量时，从活动表恢复全部原变量（未使用变量补零），对每一条**原始**约束精确代回，包括末节点、被删除的真行和经过约分的行。全部通过才可发布 FEASIBLE；只按原变量判定整数性。
5. **冲突路径。** 对越界行 `b = β + Σ aⱼ yⱼ`，若需要提高 `b`，用正项的上界和负项的下界计算可达上界 `U`，须有 `U < lower(b)`。若需要降低 `b`，用正项的下界和负项的上界计算可达下界 `L`，须有 `L > upper(b)`。每个非零项所需的界都必须存在并有来源，阻挡方向须经复核。借助等式解集不变量、边界来源和预处理映射，才能从这个局部矛盾推出原问题 UNSAT。对于归一化表达式 `s′ⱼ=sⱼ/gⱼ`，恢复原行时常数与极值乘 `g_b`，项系数乘 `g_b/gⱼ`。常数正行是另一条独立的 UNSAT 路径。公开 `SxConflict` 是局部阻挡依据，未包含完整的原约束线性组合；`row` 和 `bound_source_row` 也须分别解释。
6. **控制与终止。** 当前规则按固定编号选择越界基变量与可调整的非基变量。上限用尽时，若还需下一次换基则给 PIVOTS UNKNOWN；已经可行或已有严格冲突时仍可完成。部分正确性、有限预算下退出、无预算算法终止是三个不同命题。对有限预算的终止证明还依赖扫描、算术和清理子过程终止；本轮不以无预算终止或整数完备性作为已知定理。

## 5. 内存、资源与环境的验收边界

- 初始化建立空结果。调用返回时临时表、克隆、预处理和临时算术对象均已回收，只有结果拥有的对象可留给调用者。任一步失败，包括最后复核或发布前超时，均销毁未完成的候选；不得留下部分见证或部分冲突。
- `sx_result_clear` 释放完整结果并恢复空态，可重复调用。复用结果前先 clear；init 不负责释放旧的内容。调用方不浅拷贝拥有动态内存的结果，不单独释放其子对象。UNKNOWN 没有可续算表，重试须从原输入重新调用。
- `limits == NULL` 或对应限额字段为零时使用有限默认：全调用受控显式分配 256 MiB，最多 100000 次换基，时间 10000 ms。算术事务字节和 limb 另有限额。空间指标不含调用方输入、系统分配器隐藏开销或进程 RSS。动态大小的加法、乘法和索引均须在使用前证明安全或进入尺寸失败路径。
- 时间预算在安全检查点读取单调时钟，不承诺精确墙钟抢占。时钟故障、重入、内部不变量破坏与正常超时分别传播。进程被外部杀掉没有正常 C 返回，不属于返回表中的任何一行。
- 证明交付时明确列出已验证代码和假设，例如分配器及释放、单调时钟、线程局部作用域、算术事务异常退出与清理、MiniGMP 原语。如果使用抽象模型，需另列实际 C 实现到模型的精化义务；有未解除的假设时，应将结论标为条件性结论。

## 6. 最小语义验收实例

下表的确定结果用于正常、资源充足的执行。证明时应以精确输入行及实际控制路径建立条件；在任意有限预算下，不能无条件要求相同结果。

| 原始输入 | 所检验的性质 |
|---|---|
| 空链表、`n=2`；空链表、`n=0` | 分别返回零向量和空向量，Q FEASIBLE / Z SAT。 |
| `n=0`，单行 `−3 ≤ 0` 或单行 `1 ≤ 0` | 前者有空见证，后者 Q/Z UNSAT；均只读取常数项。 |
| 两行 `2x−1 ≤ 0`、`1−2x ≤ 0` | 唯一有理解 `x=1/2`。Q FEASIBLE / Z UNKNOWN，保留精确见证。 |
| `1−x ≤ 0`、`x ≤ 0` | 相加得到 `1 ≤ 0`，Q/Z UNSAT。第二行放在最后一个有效节点也必须参与。 |
| `2x−1 ≤ 0`、`−x ≤ 0` | `x=0` 与 `x=1/2` 都满足。检验“给出分数见证”不能推出“没有整数解”，不指定求解器一定选哪个见证。 |
| 非空有环链、可读节点的 `coef=NULL`；限额、分配失败注入 | 分别覆盖安全可检测错误、资源 UNKNOWN 和 SX_OOM，核对输出为空、输入保留、结果可清理。 |

**建议的证明交付顺序**：先固定数学谓词与 C 内存表示，再验证算术与单次表操作；接着证明预处理、见证复核及两条冲突路径；最后组合两个公开入口及 init/clear 的全部退出路径。验收记录应逐项关联本 README 的性质、证明文件、依赖假设和未完成义务。P3/P4 工程契约、测试和实测可帮助定位分支，不能替代这些证明。

实现细节参见 [P2 表契约](P2_CONTRACT.md)、[P3 公共求解契约](P3_CONTRACT.md) 和 [P4 预处理契约](P4_CONTRACT.md)。
