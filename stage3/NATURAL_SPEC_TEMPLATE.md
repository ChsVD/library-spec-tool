# 自然语言推荐规约模板

本模板用于默认阶段二，实际生成提示位于 [reference.py](reference.py) 的 PROMPT。输出仍是未验证的中文参考稿；采用 QCP 的契约组织方式，不表示能够直接交给 QCP 解析。JSON 字段保持不变。

## 正文结构

    职责：函数做什么，以及选定的实现和配置范围。
    符号：解释表示、长度单位、数学常数和返回值 ret。
    规约 <名称>：
      With：逻辑参数及含义；没有时可省略。
      Require（Pre）：适用域、入口值和入口资源。
      Ensure（Post）：由入口输入计算得到的结果、数学性质与返回时的资源。

每份规约有完整的前后条件。With 声明逻辑参数，Require 将入口快照绑定到真实输入或存储内容，Ensure 使用这些不变的旧值描述结果。读取区域的初始化、仅写区域的权限、别名、全局状态、保留内容和写入范围均放在 Require/Ensure 中，不再另设 Memory、Modifies、Fail 或边界章节。已知失败/零长行为属于相应的前后条件，尚未确定的行为放入 assumptions。

observations 只记录关键源码依据；assumptions 说明具体缺口、条件性承诺和未覆盖范围；callee_requirements 说明各调用条件下希望下层提供的前后条件及资源。这些字段不能用来隐藏正文缺失的必要条件。

## 计算结果与接口要求

对确定性计算，Ensure 应直接说明输出由哪些入口值计算得到，并将结果绑定到 C 返回值和实际输出内存。简单运算直接写等式；复杂运算可以使用纯计算模型，但必须解释输入、输出、适用域和运算含义，不能只写一个未解释的 compute 名称。

自然规约要求后续形式化接口直接暴露计算结果，或提供与计算结果已证明等价的结果接口。关系式在合法域内唯一并不意味着接口已经完善。暂用关系式时仍须明确数学含义，并在 assumptions 中列出待补充的计算接口及等价连接；本阶段不要求生成 Coq 定义或证明。

计算模型回答“输出等于什么”，数学性质说明“它对应什么运算”，Ensure 中的资源描述将结果连接到实际存储。三者应同时清楚。接口尚未实现或等价引理尚未证明时必须如实标明，不能将拟议接口冒充可导入的公共定义。具体算法、递归步长和证明组织由后续通用内容阶段比较参考材料后确定。

允许“存在 R，R 等于指定计算结果”；表示层也允许存在量，例如抽象椭圆曲线点已确定而 Jacobian 坐标不唯一。不能用未绑定入口输入的存在变量代替目标计算。对于固定长度字数组，则应明确长度和每个字，保留需求规定的高位零。

生成时在同一次调用中自查：调用者能否直接引用结果，计算模型是否对应预期数学运算，结果是否绑定返回值和输出内存，待实现接口与待证明等价关系是否明确。程序并未自动验证这些性质。
## 如何组织分支

- 原地、分离等入口资源不同的场景，可以参考 SM2 写成 r_eq_a、non_alias 等命名规约。每份均可独立阅读，不能用“同上”省略资源归还；原地契约不自动适用于分离调用。
- 同一契约内的不同返回结果通常在 Ensure 中写条件与对应结论，不按实现的每个 if 机械拆分。条件必须覆盖承诺的输入域，并说明每种结果对应的资源。
- 允许存在量和析取，判断标准是输出是否精确、调用者能否使用。多份契约不必互斥；拆分和合并必须保留原覆盖，不得删除零长或合法别名情况来简化表达。
- SM2 中的“field_non_alias <= raw”表示规约之间的推导关系，并非普通分支列表。没有依据时不生成这种关系，也不宣称某个命名规约已经证明。
- 先汇总各调用点的条件和需求。不同场景的前提不能直接合取；材料缺失或需求冲突应明确报告。模板不修补调用图，也不保证已经收集全部实际调用者。

## 乘加示例：展示格式，不是已验证契约

以下示意 64 位字实现中，原地与分离两种场景的表达方式。实际生成时需从选定源码确认配置、地址安全条件和零长行为；部分重叠仍需另行确认。示例中的中文资源描述不是 QCP 谓词。

    职责：对 n 字小端整数做单字乘加，写回低 n 字并返回进位。
    符号：B=2^64 是数学基数；n 以字为单位，每字 8 字节。
          value(X)=Σ X[i]·B^i，求和区间为 0≤i<|X|；
          ret 是 C 返回值；A、D 是不可变入口列表，R 是返回时输出列表。
          F(A,D,w) 是待落实的纯乘加计算模型，输入为等长合法字列表和单字 w，
          输出为低 n 字数组与最终进位；此处 n=|A|=|D|。
          令 T=value(A)·w+value(D)，其数学含义为：
          c=⌊T/B^n⌋，R[i]=⌊T/B^i⌋ mod B（0≤i<n），|R|=n。
          这是结果的计算含义，不要求后续实现按整体大整数计算或展开。

    规约 non_alias：
      With：A、D 分别为输入和输出区域的入口内容。
      Require（Pre）：0≤n≤INT_MAX，0≤w<B；
        拥有 ap 处初始化的 n 字数组 A，与 rp 处初始化的 n 字数组 D，
        两个区域分离；|A|=|D|=n，各字属于 [0,B)；
        两区域满足选定实现的访问及指针运算要求（具体条件待确认）。
      Ensure（Post）：令 (R,c)=F(A,D,w)，ret=c；
        |R|=n，各字属于 [0,B)，保留高位零；
        value(A)·w+value(D)=value(R)+c·B^n，0≤c≤w；
        交还 ap 处内容仍为 A 的 n 字数组，与 rp 处内容为 R 的 n 字数组，
        两区域分离。若 n=0 满足前提，则 R=[]、ret=0。

    规约 r_eq_a：
      With：A 为共享区域的入口内容。
      Require（Pre）：rp=ap，0≤n≤INT_MAX，0≤w<B；
        拥有该地址处一份初始化的 n 字数组 A；
        |A|=n，各字属于 [0,B)；
        该区域满足选定实现的访问及指针运算要求（具体条件待确认）。
      Ensure（Post）：令 (R,c)=F(A,A,w)，ret=c；
        |R|=n，各字属于 [0,B)，保留高位零；
        value(A)·w+value(A)=value(R)+c·B^n，0≤c≤w；
        交还该地址处一份内容为 R 的 n 字数组，两个指针均指向此区域。
        若 n=0 满足前提，则 R=[]、ret=0。

    assumptions：F 是接口要求，并非声称已有同名 Coq 定义或证明；
      后续须落实可直接引用的计算结果接口；若沿用关系式契约，须补充并检查等价连接；
      上面的地址条件仍是占位说明，必须根据选定实现具体化；
      零长是否可使用任意指针未确认，不能仅由空列表推断；
      部分重叠及其他字宽/实现分支未覆盖。

示例要求后续形式化接口直接暴露 F 的数组结果和进位结果，或提供已证明等价的结果接口。完整算术关系、长度和字范围保留为模型的数学性质；不能只交付一个关系谓词而忽略计算接口要求。本阶段不限定递归步长或证明算法。实际草稿应尽量将占位条件落实，无法落实的必须与 assumptions 对应，不能冒充完整契约。

## 生成后的独立审核

模板中的生成自查之外，默认入口还会由新会话审核八项内容：输入域、输出精度、入口快照、资源、分支覆盖、调用需求、假设与未知、计算接口。问题修订后重新审核，默认最多一次语义修订。审核状态单独记录，不将模型判断当作证明；完整的恢复、跳过审核和阶段三交接规则见 [阶段二说明](README.md)。
