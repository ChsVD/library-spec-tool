# P0 P1 主代理验收报告

日期：2026-11-06。开发由 GPT-6.1 Sol high 子代理承担，主代理独立审查与复测。

## 结论

P0、P1 在当前明确契约范围内工程验收通过。P0 已固定来源、接口、所有权、错误诊断、边界修复公式及不变量，明确保留无预算终止性证明义务。P1 提供项目 MiniGMP 运行时和精确分数库。此结论不是完整单纯形验收，也不是 QCP 形式化验证。

## 审查与修订

- 核对原项目32位limb与WSL LP64差异。公共十进制入口不把大数传给仅按32位处理的ui/si接口。
- 审查TLS事务、longjmp捕获边界、临时块回收和成功后输出提交。旧输出在失败时保留；原始后端不作为公共API。
- 审查并推动补充分数字符串解析从零开始、1/2回归、右输入及全部输入输出同对象的失败注入测试。
- 要求增加具体诊断，避免字节预算、limb预算、除零和非法十进制统一成不可区分的返回值。
- 新代码完成格式化并使用严格警告作为错误编译；保留上游源码注释不表示其证明可转移。
- mpz_make_odd 的副本改动是显式长度边界适配。在非零规范化输入前提下没有给出旧扫描必然越界的反例，不能将该适配描述为已复现的上游漏洞修复。
- 换基代数、合法修复方向和无候选时冲突推理与选定方案一致。有限预算保证退出；不声称已证明无预算算法终止。

## 限制和后续交接

- P1不实现sx_check、表、边界循环或SAT/UNSAT判定。sx_solver_contract.h仅为未来契约。
- max_bytes是单次事务payload预算，不包含所有存活结果、分配头、事务对象或整个进程；P2须落实表及长期状态预算。
- 对象须同线程创建、使用、释放，不支持重入或信号处理器调用；raw MiniGMP函数不是公共接口。
- 没有公共独立整数导入API，未来QCP输入适配由P2实现，不能在事务外调用需要分配的raw后端来构造对象。
- 失败保留旧输出，内部状态不可续算；保守长度估计和临时对象保留可能较早触发LIMIT。
- 极接近长度硬界的真实分配未通过穷尽测试；算术和错误路径测试均不是形式化证明。
- 最小索引规则的无预算终止证明未完成，P2/P3必须保留有限换基上限且只能将耗尽解释为UNKNOWN。

当前构建目录最后保留普通构建产物。验收脚本首轮使用何种构建取决于调用前的构建状态；若重现本次完整顺序，先执行make sanitize，再执行验收脚本。
