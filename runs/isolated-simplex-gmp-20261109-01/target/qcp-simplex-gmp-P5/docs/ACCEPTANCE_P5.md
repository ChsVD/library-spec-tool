# P5 源码交付验收

2026-11-09，GPT‑6.1 Sol（high）完成 P5 交付整理，主代理在 WSL Ubuntu 24.04 中独立验收。验收以实际解包的源码为输入。交付对象是独立算术模块的 C 源码、静态库构建入口、可运行的 FME 链表示例、自编测试及工程报告。

## QCP 调用方式

正式入口为 `sx_check_qcp(head, variables, limits, &result)`。每个节点借给求解器 `variables+1` 个可读的项目大整数，第一个系数为常数项。调用方初始化空结果，在调用后依次读取运行错误、有理数结果、整数结果和可选见证，最后清理结果对象。已有输入节点继续归调用方所有。可直接编译 [完整示例](../examples/qcp_check.c)。

| 示例模式 | 观察到的结果 |
| --- | --- |
| `integer` | 有理数 FEASIBLE，整数 SAT，见证 `1/1` |
| `fraction` | 有理数 FEASIBLE，整数 UNKNOWN，见证 `1/2` |
| `conflict` | 两层均为 UNSAT，返回阻挡边界 |
| `budget` | 两层均为 UNKNOWN，诊断为换基次数上限 PIVOTS |

主代理还编译了两个独立的 C 翻译单元。调用方使用原 QCP 的 `fme_def.h` 及 `{coef,next}` 节点，另一个文件只包含交付库的公共头。输入为 `1−Mx≤0` 和 `−1+Mx≤0`，其中 `M=2^65+1`。调用方在求解结束后检查并释放全部节点和 limb，然后读取到精确见证 `1/36893488147419103233`。在只使用包内整数头的配置中也得到相同结果。此项覆盖结构、数值表示和所有权互操作，实际使用的运行时来自交付库。

## 独立复测

候选源码包有 140 个带 SHA-256 的源文件及一个成员清单。验收程序比对包内外清单与归档摘要，解压到新的临时目录，确认初始没有 `build`。临时改动 README 后，正式校验工具在普通 Python 和 `python -O` 下均拒绝该目录。恢复文件后从源码运行以下检查。

- 普通构建和 ASan/UBSan 均通过 P1–P4 自编测试与主代理的独立数学检查，开启泄漏检测和未定义行为中止。P1 有 1,010 次逐点失败注入，P2 有 4,369 次，P3 默认和全关路径分别有 8,334 和 8,564 次，P4 有 12,630 次。
- P2 从原始等式重建 204 张表并核对 133 次换基。P3 通过公共数组与链表入口验证 76 个可行、104 个不可行和 3 个资源受限案例。P4 的 59 组输入各检查 16 种优化组合，以原始系数核对见证和冲突信息。
- `make normal` 在 sanitizer 构建之后重新生成普通库。用普通链接参数编译的外部 C 程序成功运行，动态依赖表没有出现系统 GMP、ASan 或 UBSan 运行库。示例支持四种模式，候选包独立工作时不需要原 QCP 目录。使用原始头文件的额外核对依赖本地原库。
- 构建和测试后再次核对全部成员哈希。对同一份解压源码重新打包，归档字节摘要与候选包一致。

候选完整日志在开发目录 `build/p5-candidate-review/`。最终包的复核记录与摘要放在开发目录 `release/`，其中 `P5_DELIVERY_RECORD.json` 将最终归档与候选测试关联。最终复核要求比对两包清单，仅允许交付状态文档及最终验收清单变化，并在新目录独立验证归档摘要、成员哈希、普通构建、四种示例、两种头文件下的外部 C 调用及再次打包一致性。复现命令和构建依赖见 [交付说明](P5_DELIVERY.md)。

## 能力与使用边界

当前版本检查整数问题的有理数放宽。含分数的见证只确认有理数可行。全整数见证通过原始行复核才发布整数 SAT，有理数 UNSAT 同时排除整数解。配置预算耗尽、实际内存分配失败、无效输入和内部错误均有各自诊断。冲突结果给出经检查的局部表行和阻挡边界。工程验收覆盖本报告的测试平台和案例，形式化验证、完整整数求解、SMT 集成及无预算终止证明另行开展。
