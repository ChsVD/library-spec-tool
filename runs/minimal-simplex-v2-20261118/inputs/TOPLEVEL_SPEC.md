# sx_check_qcp 顶层规约输入

以下是 2026-11-13 生效修订的顶层数学与环境要求原文摘录。仅供新版自然规约实验。

## 数学输入与公开结果

```c
int sx_check_qcp(const struct InequList *head, size_t variables);
```

设 n=variables，链表有 m 个有效节点，数学矩阵为 c，维度为 m×(n+1)。定义：

`SatQ(c,x) := x∈Q^n ∧ 对每个 i∈[0,m)，c[i,0]+Σ(j=0..n-1)c[i,j+1]*x[j]≤0`。

前置条件成立且调用正常返回时，返回值只能为 0 或 1：

- 返回 0 当且仅当原系统存在有理解；不推出整数 SAT。
- 返回 1 当且仅当原系统不存在有理解；由此推出不存在整数解。
- 归还 head 指向的原输入节点和系数头对象；链表顺序、各节点地址、各节点的 next 与 coef 指针值均与入口相同，每个系数仍表示入口矩阵对应的数学整数。归还的系数持有合法、相互分离且可由调用者按正常 MiniGMP 生命周期清理的资源，合法静态 dummy 仍可共享。 归还条件约束系数头所在的地址与数学值，MiniGMP 头内的 _mp_d、_mp_alloc、_mp_size 和有效 limb 字列表由合法表示决定，不绑定为入口的具体表示。 求解器内部拥有存储全部释放。

没有公开见证、结果对象或错误状态。异常、分配失败或前置条件不成立不具有 0/1 后置条件，不能把这种情况解释成“返回0”。正常返回后置条件本身不保证函数会终止。

## 调用方必须提供的输入条件

### 链表结构与生命周期

1. head 为 NULL，或指向长度恰为 m 的有限、无环、NULL 终止链表。每个节点具有正确类型、对齐及完整可读存储，所有 next 都指向下一有效节点或 NULL。
2. 最后节点是有效约束，没有空尾哨兵。不能把旧 int SMT FME 的尾节点结构直接传入。
3. 每个节点的 coef 指向至少 n+1 个连续、已初始化、表示合法的项目 __mpz_struct；n=0 时仍须有一个常数项。
4. 调用方在调用期间保持节点、系数头及其 MiniGMP 存储有效，且不释放、移动、重分配或并发修改它们。实现仅读取输入，不释放或修改输入。归还时调用者收回节点、系数头及可清理的 MiniGMP 资源。
5. 禁止伪造重叠类型对象。输入采用与 GMP-FME 的 InequList/store_Z 相容的分离资源要求：各节点字段、各行实际读取的 n+1 个整数头及其拥有的 limb 存储资源彼此分离。不支持不同行共享系数头或拥有的 limb 存储；即使只读也不属于本接口的合法输入。合法零对象可以共同指向 MiniGMP 的静态 dummy limb，因为 store_Z_dummy 不持有该静态 limb 的独占资源。求解器借入这些资源，返回时交还同一链表和系数头上的合法对象资源。
6. 不允许信号处理器或其他线程破坏本次调用正在使用的输入及内部存储。分配器返回的新块与所有存活输入和拥有块分离。

### 系数表示

每个整数头使用本项目 vendor/gmp/minigmp/gmp_def.h 的布局，不混用系统 GMP ABI：

- `_mp_alloc` 为非负且可表示的 int，表示 limb 容量。
- `_mp_size` 为有符号有效 limb 数，不能为 INT_MIN；设 L 为其数学绝对值，则 L≤_mp_alloc。
- 非零整数具有 L≥1，前 L 个 limb 可读，最高有效 limb 非零；符号由 _mp_size 给出。
- 数值为 `sign(_mp_size) * Σ limb[k] * 2^(32*k)`。
- 零值的 _mp_size=0。允许正常 mpz_init 建立的 alloc=0、dummy limb 表示；dummy 指针不当作 malloc 所有权释放。不能任意把零对象的 _mp_d 换成 NULL 并假定所有后端函数接受。
- 分配容量对应的真实块有效，读写权限与后端实际调用规约一致；对本入口的只读输入，应满足实际 mpz_set 源参数的 store_Z 条件，从调用后取回同一头地址上的同值合法整数资源。

上面的自然语言条件须最终与后端 store_Z、store_Z_dummy 等实际表示谓词对应。使用头文件同名字段不意味着任意字段组合合法。

### 约束域

所有行均为整数系数的非严格小于等于零关系，所有原变量自由且按有理数解释。系数可负、可零、可大于机器整数，不要求行 GCD 为1。允许常数行、重复行、无用变量、全零系数和空约束。

等式由上层拆成两行。严格不等式、析取、非线性项、整数同余和不等关系不属于接口。不能把有理严格关系通过常数加减1转换成非严格关系。n 是逻辑变量维数，不是字节数或含常数的列数。

## 尺寸与地址运算前置条件

令 k=n+m，所有以下公式先在数学自然数中解释，再要求可安全转换为 C 尺寸。一个简单、保守的公开合法域为：

- m、n、k 均小于 SIZE_MAX，且 n+m 不发生 size_t 回绕；n+1 可表示。
- m*k 可表示，m*sizeof(__mpz_struct)、m*k*sizeof(__mpz_struct) 可表示。
- m*sizeof(size_t)、k*sizeof(size_t) 可表示。
- 每行 (n+1)*sizeof(__mpz_struct) 可表示且对应真实输入数组。
- 上述每个实际数组对象的字节数不超过 PTRDIFF_MAX，作为保守的 C 对象与指针运算范围条件；非空对象还须能实际成功分配。

据此可证明 build 中计数递增、variables+r、r*k+v、q->coef+v+1 及各循环索引不会回绕或越界。SIZE_MAX 被保留为“非基／未找到”的哨兵，不是有效行号或变量编号。

这些约束不替代后端 limb 容量条件，也不保证物理内存充足。避免只写“m和n是size_t”而漏掉它们的和、乘积、字节乘积和索引。

## 外部运行环境与分配服务假设

使用与后端一致的 C 实现：unsigned int 为 32 位，字节和宽整数类型、移位及乘法所需宽度满足项目后端规约。形式化证明采用 GMP-FME 和原 MiniGMP 的 QCP naive_C_Rules（Arch32 BigEndian）；size_t 以 32 位 unsigned int 建模，SIZE_MAX=2^32−1，对象字节跨度采用 2^31−1 的保守上界。WSL Ubuntu x86-64 用于工具运行和历史本机测试；模型与布局的实测见 ../../proof/VERIFICATION_PLAN.fme-model.md。

对本次调用实际执行的每一个非零大小分配，假设其返回满足对齐、大小、独占读写权限的新块，并且释放操作符合标准 C 分配器契约。该假设覆盖表数组、索引数组、后端 limb、临时 mpz 头及除法逆元对象。

零大小分配可返回 NULL 或可释放的唯一指针：当前 integers(0) 和索引空数组不会解引用返回值，正常清理只调用 free。不能在证明中无理由要求 malloc(0) 必然非空。

## 大整数增长和后端调用条件

初始系数合法不充分：整数换基会扩大 D、C、A，后端 GCD、乘法、除法还会申请临时容量。必须保证执行中每次调用及其内部子调用的有符号长度、位数、分配字节、指针偏移均可表示，并满足该函数的正式前置条件。

典型义务包括乘法的两个有效长度之和、加法的进位容量、GCD内部移位或位数计算、除法的商余数与逆元临时容量，以及把limb数转换到int后的非负和上界。不能只对输入或最终结果作长度限制。

可将该环境条件命名为 `BackendCapacityOK(trace)`，表示实际执行轨迹中所有后端容量表达式合法。这是明确的条件化证明接口，目前还不是从(m,n,输入位数)得到的静态充分界。若后续要求仅凭输入参数给出可执行前置条件，则必须另外推导中间增长界，或将可证明输入限制为一个有明确界的子域；不得把未证明的界伪装成已保证。

不照搬旧模块的 max_limbs 默认值或运行时限制来代替此证明，也不增加容量检查分支。
