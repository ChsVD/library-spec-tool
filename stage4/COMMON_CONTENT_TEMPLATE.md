# 阶段四复用参考交付模板

程序为同一次运行保存逐函数检索问题、整批共享参考、独立审核结果和 Markdown 交接说明。以下问题用于生成和审核。具体机器字段由 `prompts.py` 与 `contracts.py` 定义。

| 文件 | 要回答的问题 |
|---|---|
| `functions/<函数ID>/common_needs.json` | 哪条上游规约、哪个实现位置需要查参考？上游列出了哪些已有需求？本轮又提取了哪些检索问题？ |
| `candidate.json` | 共享参考来自哪个文件和行区间？定义或引理表达什么，前提是什么？哪个函数在什么条件下可直接参考、需要适配或只能借鉴思路？ |
| `planning.json` | 本批需求、原文、函数使用说明如何关联？哪个版本的候选接受了审核？ |
| `review.json` | 共享原文的解释是否准确？各函数推荐是否保留原有条件和目标端限制？哪些判断应修订或暂缓采用？ |
| `candidate.md` | 后续 QCP agent 可从哪里找到已认可参考，哪些调用或资源条件仍待确认？ |
| `reference_strategies/index.json` | 哪些参考有直接关联的规则？规则使用哪些依赖，其原文和证明位置在哪里？ |

本版报告标记 `protocol_version=3`。`references` 的每条记录用 `id` 关联 `name`、`meaning`、`premises` 和 `evidence`。原文区间包含文件、起止行，需在当前角色的读取范围内。`uses` 的每条记录用 `function_id` 和 `need_id` 定位检索问题，列出相关 `reference_ids`。同一条使用说明有独立的 `id`，供审核者定位。

| `result` | 交接内容 |
|---|---|
| `direct` | 说明在目标函数的哪个位置可以参考原内容。 |
| `adapt` | 说明参考内容与目标接口间需要适配的条件。 |
| `idea` | 指出可借鉴的思路及阻止直接使用的差异。 |
| `not_found` | 记录实际查过的范围和阅读证据，参考 ID 列表为空。 |
| `uncertain` | 写明具体疑点，可保留已找到的候选。 |

所有使用说明的 `target_status` 为 `not_validated`。`review.json` 的 `candidate_digest` 绑定本次候选；`reference_reviews` 审查原文解释，`use_reviews` 审查函数推荐。推荐获认可且引用的参考也获认可，才会进入 `candidate.md` 的可参考清单。

例如检索零长度数组时，找到 mini-GMP 的 `mpd_store_Z_zero_to_emp` 后，记录其原文、方向和使用条件。在 OpenSSL 的函数说明中写明 `UInt64Array` 的空数组资源如何从调用者前提得到仍需在目标端测试。若另一个需求没有查到结果，记录实际检索范围；若存在候选但适用性尚不明确，写出疑点。二者均可与已认可的参考一起交接。

没有直接相关的 strategy 时记录原因或查找范围，附件列表可为空。有关联时，程序按坐标提取选定规则原文，证明位置尚未定位时描述本次阅读情况。索引标明 `installed=false`、`target_status=not_validated`。已证明库的使用前提、引理方向和目标差异都属于审核对象。

结构校验能检查引用标识、文件区间和本角色的阅读记录。引理方向是否被写反、推荐是否遗漏关键条件，依赖独立审核者的语义判断。固定模型响应用来检验工具如何处理这些反馈。报告修订后以新候选及对应审核为准。

旧版规划协议使用 `items`、`coverage` 和逐项验证义务。阅读旧实验时按当时的版本解释其状态。
