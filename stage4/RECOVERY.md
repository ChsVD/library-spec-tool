# 阶段四报告修复与重新校验

报告被拒绝后，保存原始响应、完整报告、会话及校验错误，再按原因定向修复。报告超长只是其中一种情况。修复后重新执行完整校验，候选通过后继续独立审核。

## 使用

```bash
python3 -m stage4 --input input --stage3-run runs/specs \
  --recover-from runs/failed-common --output runs/repaired-common \
  --max-report-chars 32000
```

模型、推理强度、输入、上游范围、角色要求和任务预算须与原运行一致；需沿用原运行非默认参数。输出必须是新目录，不能位于旧目录中，不与 --resume 合用。

--max-report-chars 为正整数或 unlimited，默认 24000。提示和所有角色报告校验共用此值。它不修改上下文、时间、调用次数等预算；只有用户显式设置时才改变报告上限。--resume 仍用于配置不变的续跑，--recover-from 用于在新目录恢复停止的任务。

## 按错误修复

| 情况 | 行为 |
| --- | --- |
| 改变长度上限后原报告已经合法 | 程序先重验保存的报告；不重新调用生成模型，继续后续审核 |
| 报告超长且限制不变 | 向模型反馈原错误，精简重复内容，保留需求、假设和引用 |
| 需求覆盖遗漏、关联 ID 错误等结构问题 | 保留原会话和完整报告，模型定向修订，完整重新校验 |
| 引用原文未收到 | 只计算缺少的引用行，实际交付后由模型确认或修改报告；不后台读取后自动宣布通过 |
| JSON 不合法 | 保存实际收到的原响应和解析错误，进行有界格式修复，不重新开展整个分析 |

普通源码和源码包均支持有界补读，单次计划最多 80 行、8 个动作；恢复补充原文还受 6000 字符预检及会话预算约束。源码包不允许读取包外材料。静态定位不算模型已读；已有阅读记录在恢复时核对内容哈希。

## 恢复检查与限制

- 只恢复停止的提取、候选生成或独立审核任务；不是把审核者的 needs_revision/insufficient 改成 pass。
- 核对运行配置、输入快照、目标范围、检查点摘要、已完成提取，以及保存报告和原始 finish/patch_report 历史是否一致。
- 已完成提取直接复用。恢复审核时保留原候选；候选需要改变应走原有修订与重新审核流程。
- 保存恢复前后报告长度配置、原文件哈希和任务来源；恢复期间再次检查旧文件未变化。
- strategy 附件仍须满足候选关联、索引摘要和文件哈希检查。修改候选后重新生成当前附件索引。
- 没有合法报告时保留原响应与会话供修复；无法在原预算内处理时继续报告未完成，不保证任何失败均可自动修好。
- 普通报告恢复不能隐式改变输入或函数范围。补材料应使用独立记录的 [输入修订流程](REVISION.md)；恢复该修订运行时保留相同转换与来源配置，不复制实验固定数量或路径。
- 旧提示或其他策略版本不同的运行仍可能被拒绝，不能为了恢复放宽一致性检查。

## 文件与状态

旧目录保持原样。新目录包含 recovery.json（来源、哈希、配置变化、复用提取），以及恢复任务的 restored-report-validation.json、resume-evidence-completion.json（适用时）、原始响应、报告尝试和完整会话。最终 candidate、planning、review 和参考 strategy 附件继续使用现有格式。

修复通过不是证明通过；候选仍为 not_proved。只有独立审核通过才为 common_candidates_reviewed，失败则保留 incomplete 及具体任务原因。
