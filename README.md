## 工具适用范围

# 相似库辅助规约生成工具开发概要

> 2026-10-20 当前流程：独立源码提取（每函数一个.c，含callee声明及已有QCP规约、宏和依赖）→人工审核/适配→固化版本→自然规约生成与审查。默认阶段2要求`--prepared-source`，不再自动提取或补包；callee规约缺失返回准备步骤，不读取其完整实现推断。命令与审核约定见[源码准备流程](SOURCE_BUNDLES.md)。下文涉及自动提取、自动补包的描述为历史设计。


> 2026-10-19 更新：默认采用[按函数源码包与独立规约子任务流程](SOURCE_BUNDLES.md)。源码提取后逐函数起草，不等待全组关系发现；阶段三也限定读取源码包。下文原库直接读取和全图先行调度描述仅适用于 legacy 历史流程。

更新日期：2026 年 10 月 18 日。

工具通过阅读待证明库和相似的已证明库，生成自然语言候选规约、QCP 所需公共定义与候选引理、函数规约，经独立 agent 审查后交给 QCP agent 证明。第一版只跑通一个目标模块和一个主要参考库，暂不处理 strategy，不以整库证明成功为目标。

主流程：模块分析与选择 → 自顶向下生成自然语言规约和调用需求 → 按清单准备公共内容 → 生成 QCP 规约 → 独立审查与修订 → QCP 证明和反馈。自然语言分析从上层需求向下推进；公共内容和证明按依赖组织，不强求同一方向。

**阶段 0：准备输入和分析约束。** 清点目标库与参考库、已有需求和文档、QCP 文档及 case lib，记录版本、允许读取的材料范围和缺失项。明确工具的分析目标和通用审查要求，不预先选择试验模块，也不提前提供模块划分答案。交付输入清单及分析约束；后续阶段需要的运行依赖按需补齐。

**阶段 1：依赖优先选择与分层比较。** 主agent在划分待证明库与各参考库的模块时生成职责/边界卡片和依赖图；选择agent先依据目标库依赖关系提出下一模块。专门初筛agent只比较职责与边界，匹配后才派发目标与参考模块的详细理解任务；比较和独立审查按模块对分别执行。未知、循环和新发现的目标依赖不能被当作已解决条件。选择即时保存，最终仍由用户审核。详见[阶段1流程](STAGE1_PLAN.md)。

**阶段 2：自然语言候选规约。** 直接使用已有模块说明、目标函数实现，以及参考库实现、规约和 Coq 材料起草，不重新开展全库模块分析。围绕具体规约缺口定向补读；有调用时才向下传递需求。明确抽象功能、环境假设、参数前提、结果、状态变化及边界，记录参考适配条件和公共内容需求。独立 agent 核对原文并检查规约过弱、过强或遗漏差异等问题，有限修订后交接。详见[阶段 2 开发思路](STAGE2_PLAN.md)。

**阶段 3：公共定义和候选引理。** 利用自然语言规约、目标实现和来源材料，按以下清单逐项判断已有可用、需要新增、不适用或尚不确定：

- 数学对象及具体数据到数学对象的表示关系。
- 数组长度、有效长度、容量、下标和元素范围及其关系。
- 合法状态、有效内存区域、资源、别名及重叠条件。
- 按需提供读取、更新、切片和拼接对表示的影响。
- 表示转换、长度关系、范围推导、状态保持等辅助引理。
- 多个函数共享的规约条件。

新增内容注明来源、用途、依赖和验证状态；起草函数规约时允许继续补充。测试条件遗漏、重复生成和无依据假设。通过标准是必要概念有出处或候选定义，缺口明确，未证明引理没有被视为已知事实。

**阶段 4：QCP 函数规约。** 将自然语言规约和公共内容转为初步形式化规约，注明各项关键保证的表达位置、新增前提及依据、未表达内容和依赖。条件允许时执行语法、解析和类型检查。测试保证遗漏、前提被无故加强、失败分支缺失。通过标准是关键需求有对应表达，工具障碍明确，产物可进入独立审查；基本检查通过不等于规约充分或函数正确。

**阶段 5：独立审查与修订。** 独立 agent 阅读原始需求、实现、相关来源材料、自然语言规约及生成内容，输出可交付证明、需要修改、工具支持待确认或需要人类处理。错误返回对应阶段，必要时修改自然语言规约。疑似 QCP 限制先查文档或做最小检查；确认无法支持后停止报告。需求与实现冲突不能靠弱化规约消除。默认连续自动修订最多三轮，可配置；同一问题反复出现且无新证据时提前停止。主动植入长度遗漏、保证删除、无依据前提、引理状态错误及工具能力误判进行测试，同时检查误报。

**阶段 6：QCP 交接和反馈。** 交付实现、规约、公共定义、已验证引理、待证明引理、case lib 及剩余限制。明确新增引理的证明责任，按依赖处理，禁止作为可信假设跳过。先试一个依赖较少的函数，再试一个使用共享内容的函数。表示不适用、引理不成立、规约遗漏等问题返回对应阶段。通过标准是产物可被实际使用、证明责任清楚、失败可定位；证明失败不自动允许削弱保证。

**阶段 7：完整流程和回归。** 从固定原始输入重新运行全流程，再用一个相近但有明确差异的模块检验泛化。修改一项需求或公共定义，检查下游内容是否重新审查。记录关键遗漏、不成立的对应和引理、审查漏报与误报、人工修改原因、QCP 实际使用的产物及反馈定位，不急于合成单一评分。

**执行约定。** 每次只推进一个阶段：确定输入和产物，完成最小实现，运行固定样例，审查修订，通过后保存可用结果作为下一阶段输入。保留中间结果，支持单独修改和重跑；共享定义改变后，相关下游检查状态必须重新确认。

始终区分原材料陈述、模型解释、新候选和实际检查结果。来源引理已证明不代表改写后成立；审查通过表示可以进入证明；模型不会表达不等于 QCP 不支持。策略提取留待一批函数跑通后再考虑。
